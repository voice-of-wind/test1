# 05 · 远程与协作：fetch / pull / push / PR

> 远程仓库不是"备份盘"，是**所有人共同认的那个参照点**。
> 这一章的核心只有一句话：搞清楚 `origin/main` 和 `main` 是**两个不同的东西**。

---

## 1. 远程仓库就是一个 URL 加一个名字

```powershell
git remote -v
```

```text
origin  https://github.com/you/todo.git (fetch)
origin  https://github.com/you/todo.git (push)
```

- `origin` 只是**默认名字**，没有魔法。你可以叫 `company`、`upstream`，一个仓库也可以有多个远程。
- 一个本地仓库可以有 0 到 N 个远程。`git clone` 会自动建一个叫 `origin` 的。

```powershell
git remote add origin https://github.com/you/todo.git     # 添加
git remote set-url origin git@github.com:you/todo.git     # 改地址
git remote rename origin company                          # 改名
git remote remove origin                                  # 删除
```

### HTTPS 还是 SSH

| 方式 | 地址长这样 | 认证 | 适合 |
| --- | --- | --- | --- |
| HTTPS | `https://github.com/you/todo.git` | 用户名 + **Personal Access Token**（不是密码！） | 公司网络穿透性好，配置简单 |
| SSH | `git@github.com:you/todo.git` | 本地密钥对，一次配置长期有效 | 不用天天输 token，推荐长期用 |

GitHub 从 2021 年起**不再接受账号密码**做 HTTPS 认证，必须用 token。第一次 `push` 会弹窗要密码，密码框里填 token。

配 SSH：

```powershell
ssh-keygen -t ed25519 -C "你的邮箱"
# 一路回车，然后把 ~/.ssh/id_ed25519.pub 的内容贴到 GitHub → Settings → SSH keys

ssh -T git@github.com     # 出现 "Hi xxx! You've successfully authenticated" 就通了
```

## 2. 三个容易混的东西

这是本章最重要的一张图：

```text
  本地 main                    远程跟踪分支                真正的远程
  （你的分支）                  origin/main                 （服务器上）
       │                            │                          │
       │  git push ─────────────────────────────────────────→  │
       │                            │                          │
       │                            │  ←──── git fetch ────────│
       │  ←── 只是更新这个指针 ──────│                          │
       │                            │                          │
       │  git pull = fetch + merge（或 rebase）                 │
```

- **`origin/main`（远程跟踪分支）**：存在你本地 `.git` 里的一个**只读副本**，记录"上次和远程同步时，远程的 main 长什么样"。**它不是你的工作分支**，你不能在它上面提交。
- **`main`（本地分支）**：你干活的地方。
- 服务器上那个 `main`：真正的、大家共享的。

`git fetch` 只更新 `origin/main`。**你的 `main` 和工作区一点都不会变。**

这就是为什么"我 fetch 了怎么代码没变"——因为它只更新了参照物。

## 3. `clone` 到底做了什么

```powershell
git clone https://github.com/you/todo.git
```

1. 下载所有对象（全部历史）
2. 建本地 `main` 分支
3. 建 `origin` 远程
4. 把本地 `main` 的**上游**设成 `origin/main`（所以之后 `git pull` / `git push` 不用带参数）
5. 检出工作区文件

```powershell
git clone <url> my-folder        # 换个目录名
git clone --depth 1 <url>        # 只下最新一次提交（快，但没有历史）
git clone -b feature/search <url> # 直接检出某条分支
```

## 4. `fetch` / `pull` / `push` 三兄弟

### `git fetch`：只更新参照物，不动你的代码

```powershell
git fetch                     # 更新所有远程跟踪分支
git fetch origin main         # 只更新 origin/main
git fetch --prune             # 顺手删掉远程已经删除的跟踪分支
```

**推荐习惯：先 fetch 看，再决定合不合。**

```powershell
git fetch
git log --oneline HEAD..origin/main      # 远程有哪些我没有的提交 ← 先看
git diff HEAD origin/main                # 远程到底改了什么     ← 再看
git merge origin/main                     # 确认了再合
```

`HEAD..origin/main` 这个语法值得记：**左边的点右边 = "右边有、左边没有的"**。

### `git pull`：= fetch + merge（或 fetch + rebase）

```powershell
git pull                      # 等价于 git fetch && git merge origin/main
git pull --rebase             # 等价于 git fetch && git rebase origin/main
```

`pull` 是个"组合命令"，它把两步糊在一起，所以你没法在中间检查。**新手期建议：重要分支上手动 fetch + 看 + merge**，只有在自己明确知道要什么时才 `pull`。

配置默认行为（README 里已经配过）：

```powershell
git config --global pull.rebase false    # pull 默认 merge
git config --global pull.ff only         # 或者：只允许快进，否则报错让你自己决定
```

> Git 2.27 之后如果不配这个，`git pull` 会警告你"行为未指定"。配好就不会再啰嗦。

### `git push`：把本地提交送上去

```powershell
git push                              # 推当前分支到它的上游
git push -u origin feature/search     # 第一次推，顺便建立上游跟踪（-u = --set-upstream）
git push origin main                  # 明确指定远程和分支
git push --tags                       # 推所有 tag（tag 默认不会跟着 push 走！）
git push origin --delete feature/search  # 删远程分支
git push --force-with-lease           # 强推（危险，见下）
```

`-u` 只需要第一次用。之后 `git push` / `git pull` 就知道该找谁，`git branch -vv` 里也会显示跟踪关系。

## 5. push 被拒：non-fast-forward

```powershell
git push
```

```text
To https://github.com/you/todo.git
 ! [rejected]        main -> main (non-fast-forward)
error: failed to push some refs to 'https://github.com/you/todo.git'
hint: Updates were rejected because the tip of your current branch is behind
hint: its remote counterpart. Integrate the remote changes (e.g.
hint: 'git pull ...') before pushing again.
```

**原因：远程上有你没有的提交。** 你的 push 会"覆盖"掉别人的工作，Git 拦住了。

这不是错误，是保护。两种正确解法：

**解法 A：合并（默认，安全）**

```powershell
git pull                # 把远程的合进来，可能产生 merge commit
# 解决可能的冲突
git push
```

**解法 B：变基（历史更干净，适合自己一个人用的分支）**

```powershell
git pull --rebase       # 把你本地的提交"重放"到远程最新提交之后
git push
```

### 关于 `--force`

```powershell
git push --force              # ❌ 会把别人的提交直接从远程抹掉
git push --force-with-lease   # ✅ 只有远程没被别人动过时才强推
```

`--force` 是**团队协作里的重罪**：别人刚推的提交会被你覆盖，而且他们本地还留着，一推又回来了，历史彻底乱掉。

唯一合法场景：你 rebase 了自己**独占**的分支（还没别人基于它开发）。

**如果一定要用，永远用 `--force-with-lease`**：它会检查远程是否还是你上次看到的样子，被别人动过就拒绝。

## 6. PR / MR：网页按钮背后是哪些命令

以 GitHub 的 Pull Request 为例，你点的那几个按钮，实际上对应：

| 你在网页上做的 | 背后等价于 |
| --- | --- |
| 创建 PR | 平台比较 `main` 和 `feature/x` 的 diff，开一个讨论区 |
| 本地推新提交到同一分支 | `git push`（PR 会自动更新） |
| Review 里提意见 | 没有命令，纯评论 |
| "Update branch" 按钮 | `git merge main`（或 rebase）到你的分支 |
| Squash and merge | `git merge --squash` + 一次提交 |
| Merge pull request | `git merge --no-ff` |
| Rebase and merge | `git rebase main && git merge --ff-only` |
| 合并后删分支 | `git push origin --delete feature/x` |

### 一个完整的协作循环

```powershell
# ① 从最新主干开分支
git switch main
git pull
git switch -c feature/search

# ② 开发，提交（可以多次）
git add -A
git commit -m "feat(store): 支持按关键词搜索"

# ③ 推送，第一次带 -u
git push -u origin feature/search

# ④ 网页上开 PR，等 review

# ⑤ 收到意见，改代码，追加提交（不要 amend 已推送的提交！）
git add -A
git commit -m "fix: 按 review 意见处理空关键词"
git push

# ⑥ 合并后，清理本地
git switch main
git pull
git branch -d feature/search
```

### review 别人的分支，怎么在本地跑起来

```powershell
git fetch origin
git switch -c review/feature-search origin/feature/search   # 拉下来单独看
# 跑测试、点一遍
git switch main
git branch -D review/feature-search
```

或者不切分支直接看 diff：

```powershell
git fetch origin
git diff main...origin/feature/search     # 三个点：从分叉点开始比，只看这条分支带来的改动
```

> `A..B` 和 `A...B` 的区别：两个点是"B 比 A 多的提交"，三个点是"从共同祖先分叉之后 B 的改动"。**review 用三个点更准**，否则会把主干上的别人的改动也算进来。

## 7. Tag：给提交打上版本号

分支会动，**tag 不会动**。发布版本用它。

```powershell
git tag                              # 列出所有 tag
git tag v1.0.0                       # 轻量 tag：只是个指针
git tag -a v1.0.0 -m "第一个可用版本"  # ★ 附注 tag：带作者、日期、说明，发布用这个
git tag -a v1.0.1 9fceb02 -m "补丁"   # 给历史某个提交打 tag
git show v1.0.0                      # 看 tag 指向的提交
git push origin v1.0.0               # 推单个 tag
git push --tags                      # 推所有 tag
git tag -d v1.0.0                    # 删本地 tag
git push origin --delete v1.0.0      # 删远程 tag
```

**最常见的翻车点：`git push` 不会推 tag。** 打完 tag 必须单独 `git push --tags`，否则远程上没有。

版本号约定（语义化版本）：

```text
v1.4.2
  │ │ └─ 补丁：修 bug，不改接口
  │ └─── 次版本：加功能，向后兼容
  └───── 主版本：不兼容的改动
```

## 8. 没有网络怎么练：本地裸仓库

**"远程仓库"技术上就是另一个 Git 仓库。** 用一个裸仓库（bare repo，没有工作区，专门当服务器用）就能完整模拟团队协作，命令完全一样：

```powershell
git init --bare D:\git-remotes\todo.git    # 这就是"服务器"
git remote add origin D:\git-remotes\todo.git
git push -u origin main
git clone D:\git-remotes\todo.git project-bob   # 这就是"同事的电脑"
```

lab05 就是用这个方式练的，**不需要 GitHub 账号**。学会之后换成 https 地址，操作一模一样。

## 9. 这一章的四句话

1. **`origin/main` 是本地的一个参照物，不是远程本身。**
2. **`fetch` 只更新参照物；`pull` = fetch + merge。**
3. **push 被拒 = 远程有你没有的提交，先 pull 再 push。**
4. **tag 要单独 push。**
