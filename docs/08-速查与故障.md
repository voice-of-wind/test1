# 08 · 速查表与故障排查

---

## 一页速查（按场景找命令）

### 看状态

| 我要 | 命令 |
| --- | --- |
| 现在什么情况 | `git status` / `git st` |
| 我改了啥（没 add） | `git diff` |
| 我即将提交啥 | `git diff --staged` |
| 一共改了哪些文件 | `git diff --stat` |
| 历史长什么样 | `git lg`（= `log --oneline --graph --all --decorate`） |
| 这个文件谁改的 | `git blame <file>` |
| 谁改过这段代码 | `git log -S "代码片段"` |
| 某个版本的文件长什么样 | `git show <哈希>:<路径>` |

### 提交

| 我要 | 命令 |
| --- | --- |
| 提交全部改动 | `git add -A && git commit -m "..."` |
| 挑着提交 | `git add -p` |
| 补上漏掉的文件 | `git add x && git commit --amend --no-edit` |
| 改提交信息 | `git commit --amend -m "新信息"` |
| 撤销上一次提交（留改动） | `git reset --soft HEAD~1` |

### 分支

| 我要 | 命令 |
| --- | --- |
| 开分支并切过去 | `git switch -c feature/x` |
| 切分支 | `git switch main` |
| 切回上一个分支 | `git switch -` |
| 看所有分支+跟踪关系 | `git branch -vv` |
| 删本地分支 | `git branch -d feature/x`（未合并用 `-D`） |
| 删远程分支 | `git push origin --delete feature/x` |
| 改名 | `git branch -m old new` |

### 合并

| 我要 | 命令 |
| --- | --- |
| 合并分支 | `git merge feature/x` |
| 合并并保留分支痕迹 | `git merge --no-ff feature/x` |
| 放弃这次合并 | `git merge --abort` |
| 冲突标记为已解决 | `git add <file>`（然后 `git commit`） |
| 检查还有没有漏掉的标记 | `git diff --check` |

### 远程

| 我要 | 命令 |
| --- | --- |
| 看远程地址 | `git remote -v` |
| 只更新参照物 | `git fetch`（`--prune` 清已删分支） |
| 拉取并合并 | `git pull` |
| 拉取并变基 | `git pull --rebase` |
| 推当前分支 | `git push` |
| 第一次推并建立跟踪 | `git push -u origin feature/x` |
| 推 tag | `git push --tags` |
| 看远程有啥我没有 | `git log HEAD..origin/main --oneline` |
| 看远程改了什么 | `git diff HEAD origin/main` |

### 救火

| 我要 | 命令 |
| --- | --- |
| 丢弃某个文件的工作区改动 | `git restore <file>` |
| 取消暂存 | `git restore --staged <file>` |
| 丢弃所有未提交改动 | `git restore .`（或 `git reset --hard`，更危险） |
| 撤销已推送的提交 | `git revert <哈希>` |
| 找回 reset --hard 丢掉的东西 | `git reflog` → `git reset --hard 'HEAD@{n}'` |
| 放弃 rebase | `git rebase --abort` |
| 放弃 cherry-pick | `git cherry-pick --abort` |
| 临时收起来 | `git stash push -u -m "说明"` |
| 取回来 | `git stash pop` |

## 20 个"我该怎么办"

### 1. 提交到错的分支了

```powershell
git log --oneline -1                      # 记下哈希
git reset --soft HEAD~1                   # 从这个分支撤掉（改动还在）
git stash push -m "放错地方的改动"
git switch 正确的分支
git stash pop
git commit -m "..."
```

已经推送了的话：先在错的分支上 `revert`，再去对的分支重做。

### 2. 提交里漏了一个文件

```powershell
git add 漏掉的文件
git commit --amend --no-edit
```

### 3. 提交信息写错了

```powershell
git commit --amend -m "正确的信息"        # 只限最后一次
```

### 4. 提交信息写错，但已经 push 了

如果只有你自己在用这条分支：

```powershell
git commit --amend -m "正确信息"
git push --force-with-lease
```

如果别人也在用：**别改**，忍着。历史一致性比一句错别字重要。

### 5. 想把最近 3 条碎提交合成 1 条

```powershell
git rebase -i HEAD~3        # 后两条改成 squash 或 fixup
```

### 6. 想改历史里第 5 条提交的信息

```powershell
git rebase -i HEAD~5        # 把那条的 pick 改成 reword
```

### 7. 不小心 `reset --hard` 了

```powershell
git reflog                              # 找到丢掉之前的位置
git reset --hard 'HEAD@{1}'             # PowerShell 里必须加引号！
```

### 8. 删了一个没合并的分支

```powershell
git reflog                              # 找到那条分支最后的提交
git switch -c feature/救回来 <哈希>
```

### 9. push 被拒（non-fast-forward）

```powershell
git pull --rebase        # 或 git pull（合并方式）
# 解决冲突（如果有）
git push
```

### 10. 冲突解到一半想放弃

```powershell
git merge --abort        # merge 中
git rebase --abort       # rebase 中
git cherry-pick --abort  # cherry-pick 中
```

### 11. 冲突解完了，但功能坏了

说明"语法对、语义错"。回头 `git diff HEAD` 看这次合并动了什么，把丢掉的那部分补回来。**下次记住：解完跑测试。**

### 12. 不小心 commit 了一个大文件 / 密钥

**还没 push：**

```powershell
git rm --cached 大文件
echo "大文件" >> .gitignore
git commit --amend --no-edit
```

**已经 push：** 事情严重了。密钥要立刻作废轮换（历史已经泄露），然后用 `git filter-repo` 清理历史（团队协作，必须全员配合）。

### 13. 想把某个文件恢复到某个版本

```powershell
git restore --source=<哈希> <file>
git show <哈希>:<file> > file            # 或者导出内容
```

### 14. 想看某次提交到底改了什么

```powershell
git show <哈希>
git show <哈希> --stat                   # 只看文件列表
git show <哈希> -- <file>                # 只看某个文件
```

### 15. 想撤销某一次（不是最近一次）提交

```powershell
git revert <哈希>        # 已推送的用这个
git rebase -i <哈希>~1   # 没推送的，把那条 drop 掉
```

### 16. 本地一堆分支，哪些能删

```powershell
git branch -vv                     # 看哪些没有 [origin/...]
git branch --merged main           # 已合并进 main 的（可安全删）
git branch -d <那些>
git remote prune origin            # 清掉远程已删的跟踪分支（或 fetch --prune）
```

### 17. `git status` 显示 modified，但 `git diff` 是空的

通常是换行符问题（CRLF/LF），或者只是文件权限/时间戳变了。

```powershell
git diff --stat
git add --renormalize .
git status
```

还不行就 `git config --global core.autocrlf false` 配 `.gitattributes`（见 docs/07）。

### 18. 中文文件名显示成 `\346\226\207\346\241\243`

```powershell
git config --global core.quotepath false
```

### 19. `git log` 里中文是乱码

终端编码问题：

```powershell
chcp 65001
$env:PYTHONUTF8 = "1"
```

git 本身存的是 UTF-8，不会损坏，只是显示问题。

### 20. 完全乱了，想重来

```powershell
# 只想丢掉未提交的改动
git restore .

# 想回到远程的状态（本地提交全丢，慎用）
git fetch
git reset --hard origin/main

# 练习仓库彻底重来
tools\reset-practice.ps1
```

## Windows / PowerShell 专属坑

这些是 Windows 上独有、Linux 教程里不会提的。

### 1. `HEAD@{1}` 必须加引号 ★

`@{...}` 在 PowerShell 里是哈希表语法，会被提前解析：

```powershell
git reset --hard HEAD@{1}       # ❌ unknown switch `e'
git reset --hard 'HEAD@{1}'     # ✅
```

同样的还有 `git stash show stash@{0}` → 写成 `git stash show 'stash@{0}'`。

### 2. 路径用正斜杠或引号

```powershell
git add todo\cli.py             # 能用
git add todo/cli.py             # 更保险（Git 自己认）
git diff -- "docs/我的 文档.md"  # 有空格必须引号
```

### 3. 通配符会被 PowerShell 先展开

```powershell
git add *.py            # ⚠️ PowerShell 先展开成文件列表
git add "*.py"          # ✅ 交给 git 处理（但注意：git 的 *.py 也匹配子目录）
```

### 4. 中文输出乱码

```powershell
chcp 65001
```

想永久生效写进 `$PROFILE`（见 README 环境准备）。

### 5. `git commit -m "多行信息"` 在 PowerShell 里怎么写

```powershell
git commit -m "feat: 标题" -m "正文第一段" -m "正文第二段"
```

多个 `-m` 会变成多个段落（中间空行）。**别用 `` `n `` 拼**，PowerShell 和 git 对换行的处理容易出错。

### 6. 编辑器弹不出来 / 弹出来是 vim

```powershell
git config --global core.editor notepad
# 或者 git config --global core.editor "code --wait"
```

vim 里想退出：`Esc` → `:wq` → 回车（保存退出），`:q!` → 回车（不保存退出）。

### 7. Git 说 `detected dubious ownership`

仓库目录的属主和当前用户不一致（常见于共享盘、WSL 混用）：

```powershell
git config --global --add safe.directory D:/path/to/repo
```

### 8. 路径太长报错

```powershell
git config --global core.longpaths true
```

## 出事时的固定动作

不管遇到什么，先按这三步看：

```powershell
git status                          # 我在哪、有没有没做完的事
git log --oneline --graph --all -15 # 历史长什么样
git reflog -20                      # 我最近都干了什么
```

90% 的"诡异问题"，这三条命令的输出里就有答案。

**然后记住两条禁令：**

- 慌的时候**不要** `git push --force`
- 慌的时候**不要** `git reset --hard`

先看清楚，再动手。Git 几乎不真的删东西，你有 reflog。
